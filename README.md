# Namibia Market Access Network

**Code Blossom Hackathon 2026 — Group 5**

Market Access is a digital marketplace designed to connect **Namibian farmers and producers with buyers** such as hotels, restaurants, schools, retailers, and other businesses.

The platform allows buyers to publish what agricultural products they need and enables producers to find relevant market opportunities. An intelligent matching engine evaluates available supply and buyer demand based on **product compatibility, quantity, price, distance, transport cost, and recurring demand**.

---

## Problem

Many agricultural producers struggle to consistently find reliable markets for their produce, while businesses often struggle to find suitable local suppliers.

This can lead to:

* Unsold agricultural produce
* Missed business opportunities
* Difficulty finding reliable suppliers
* High transportation costs
* Poor coordination between producers and buyers
* Limited visibility of available demand

Market Access aims to bridge this gap by creating a centralized digital marketplace for agricultural supply and demand.

---

##  Solution

Market Access connects the two sides of the agricultural market:

###  Producers / Sellers

Producers can:

* List available agricultural products
* Specify available quantities
* Set prices
* Provide their location
* View potential buyers
* View matches generated by the matching engine

### Buyers

Buyers can:

* Register as a business or organization
* Specify the products they need
* Specify required quantities
* Set their budget price
* Indicate whether demand is once-off, weekly, or monthly
* View suitable producer matches

### Transport

The platform also incorporates transport considerations so that geographically closer opportunities can receive higher match scores.

# Matching Engine

The matching engine compares available producer listings with active buyer demands.

It evaluates several factors and produces a score out of **100 points**.

## Matching Factors

| Factor               | Maximum Points |
| -------------------- | -------------: |
| Product Match        |             30 |
| Quantity Feasibility |             20 |
| Price Alignment      |             20 |
| Distance             |             15 |
| Transport Cost       |             10 |
| Availability         |              5 |
| Recurring Demand     |              5 |

The algorithm prioritizes opportunities that are more commercially viable.

---

# Match Scoring

### Product Match — 30 points

An exact product match receives the highest score.

```text
Exact match       → 30
Partial match     → 20
No match          → 0
```

---

### Quantity Feasibility — 20 points

The algorithm compares buyer demand against the producer's available quantity.

```text
Demand <= Supply       → 20 points
Demand <= 1.5 × Supply → 15 points
Demand <= 2.5 × Supply → 8 points
Otherwise              → 2 points
```

---

### Price Alignment — 20 points

The seller's price is compared with the buyer's budget.

```text
Seller <= Budget       → 20 points
Seller <= 1.2 × Budget → 14 points
Seller <= 1.5 × Budget → 7 points
Otherwise              → 0 points
```

---

### Distance — 15 points

Distance is calculated using the **Haversine formula**.

```text
≤ 50 km    → 15 points
≤ 150 km   → 12 points
≤ 300 km   → 8 points
≤ 500 km   → 4 points
> 500 km   → 1 point
```

---

### Transport Cost — 10 points

Estimated transport cost is based on distance and shipment weight.

```text
Transport cost =
distance × 2.50 × weight in tonnes
```

The calculation has:

* Minimum charge: **N$50**
* Maximum charge: **N$20,000**

# Running the Matching Engine

Trigger matching:

```http
POST http://localhost:5000/api/matches/run
```

Example response:

```json
{
  "success": true,
  "message": "Matching completed: 12 new matches saved.",
  "data": {
    "matches_inserted": 12,
    "total_computed": 45
  }
}
```

Retrieve matches:

```http
GET http://localhost:5000/api/matches
```

Results are ordered by match score.

# Troubleshooting

### Backend cannot connect to MySQL

Check:

```env
DB_HOST
DB_USER
DB_PASSWORD
DB_NAME
```

Also make sure the MySQL server is running.

---

### Frontend cannot connect to backend

Check the frontend `.env`:

```env
VITE_PERSON_B_API_URL=http://localhost:4000
VITE_MATCH_ENGINE_API_URL=http://localhost:5000
```

After changing `.env`, restart Vite:

```bash
npm run dev
```

---

### Matching engine returns no matches

Make sure the database contains:

1. Products
2. Active producer listings
3. Open buyer demands

Then trigger:

```http
POST /api/matches/run
```
